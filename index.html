01 — Architecture

HOW IT
WORKS

1
Trigger Detection
Activates on keywords: "caveman", "/caveman", "less tokens", "be brief". Also triggers on /caveman lite|full|ultra for level selection.
2
Mode Persistence Engine
Once active, stays ACTIVE every response. No revert after many turns. No filler drift. Explicitly killed by "stop caveman" or "normal mode" only.
3
Response Transformer
Strips articles (a/an/the), filler words, pleasantries, hedging. Replaces verbose synonyms. Allows sentence fragments. Pattern: [thing] [action] [reason]. [next step].
4
Auto-Clarity Gate
Temporarily drops caveman for security warnings, destructive ops, ambiguous multi-step sequences. Resumes automatically after critical section.
5
Boundary Enforcement
Code blocks, commit messages, PRs always written normal. Caveman applies only to prose communication.
Live Response Demo
User Prompt
Why does my React component re-render every time?
Response
Sure! I'd be happy to help. Your component re-renders because you're creating a new object reference on every render. When you define an object inline as a prop, React sees it as a brand-new object each time, even if the values haven't changed. The solution is to wrap it in useMemo to memoize the reference.

06 — Sarita's Analysis

PROPOSED
IMPROVEMENTS

Priority: High
Context-Aware Compression
Currently, caveman mode applies uniform compression regardless of content type. Improvement: auto-detect explanation vs debugging vs architecture context and adjust intensity dynamically — deeper compression for simple questions, lite for complex explanations.
Reduces cognitive mismatch by ~40%
Enhancement
Token Counter Feedback
Add live token-count reporting at the end of each caveman response: [tokens: 24 vs ~90 normal]. Lets users see actual savings and calibrate which intensity level works best for their use case.
Transparency + informed level selection
New Feature
Domain-Specific Abbreviations
Ultra mode currently uses generic abbreviations (DB, auth, fn). Improvement: allow user to define a domain abbreviation map at session start. Frontend devs get JSX/TS/CSS shorthands; backend devs get ORM/RPC/gRPC.
Up to 25% additional compression in ultra
Enhancement
Wenyan Mode Calibration
Wenyan levels currently use fixed classical patterns. Improvement: auto-calibrate based on user's Chinese dialect and technical vocabulary. Detect if user prefers 台灣繁體 vs 简体 and adapt classical particle usage accordingly.
Better fit for 1.4B+ Chinese-speaking users
Priority: High
Gradual Re-entry
When auto-clarity kicks in for complex sequences, current behavior is hard-switch. Improvement: implement graceful re-entry — add one sentence of context bridge before resuming caveman mode, so the response feels coherent rather than abrupt.
Improves UX readability in critical sections
New Feature
Persistent Level Memory
Current skill has no memory of preferred level across sessions. Improvement: store user's preferred caveman intensity in Claude's memory system. "/caveman" without a level modifier auto-picks last used level instead of defaulting to full.
Eliminates repetitive level-setting overhead
